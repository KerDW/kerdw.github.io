Resumen de Explotación

La máquina expone un servicio Flowise en el subdominio staging.silentium.htb. La versión instalada (3.0.5) es vulnerable a varios CVEs encadenables. El punto de entrada comienza con la enumeración de usuarios a través del endpoint /api/v1/account/forgot-password, que responde de forma diferente dependiendo de si el email existe o no, permitiendo descubrir al usuario ben@silentium.htb.

Con el usuario identificado, se abusa de CVE-2025-58434: el mismo endpoint devuelve en la respuesta un tempToken válido que puede usarse directamente en /api/v1/account/reset-password para resetear la contraseña sin ninguna verificación adicional, lo que constituye una toma de control de cuenta (Account Takeover).

Una vez autenticados, se explota CVE-2025-59528, un RCE autenticado en el endpoint /api/v1/node-load-method/customMCP que permite inyectar código JavaScript arbitrario mediante un campo de configuración no saneado. Esto otorga acceso a un contenedor Docker donde las variables de entorno filtran la contraseña SMTP (SMTP_PASSWORD=r04D!!_R4ge), que resulta ser también la contraseña SSH del usuario ben en el host.

Ya en el host, se descubre un servicio Gogs corriendo en el puerto local 3001. La versión instalada (0.13.3) es vulnerable a CVE-2025-64111, un RCE mediante un ataque de symlink que permite sobrescribir el archivo .git/config de un repositorio con contenido controlado por el atacante, inyectando una directiva sshCommand arbitraria que se ejecuta como root. Esto se aprovecha para asignar el bit SUID a /bin/bash y escalar privilegios.

Account Takeover — CVE-2025-58434

La vulnerabilidad CVE-2025-58434 afecta al flujo de recuperación de contraseña de Flowise. El endpoint /api/v1/account/forgot-password no solo acepta el email, sino que devuelve en la respuesta el tempToken generado para el reset, sin enviarlo únicamente por correo. Esto permite a cualquiera que conozca el email tomar el control de la cuenta sin acceso al buzón de correo.

RCE en Flowise — CVE-2025-59528

Con acceso autenticado, procedo a explotar CVE-2025-59528. Esta vulnerabilidad permite la ejecución de código JavaScript arbitrario en el servidor a través del endpoint /api/v1/node-load-method/customMCP. El campo mcpServerConfig en el cuerpo de la petición no es saneado correctamente y permite inyectar y ejecutar código Node.js directamente en el proceso de Flowise.

RCE en Gogs — CVE-2025-64111

La vulnerabilidad explota un ataque de enlace simbólico (symlink attack) combinado con la API de contenidos de Gogs. El flujo es el siguiente:

  1. Se crea un repositorio en Gogs y localmente.
  2. Se crea un symlink que apunta a .git/config y se sube al repositorio.
  3. Mediante la API de Gogs, se actualiza el contenido del archivo que apunta el symlink, escribiendo un .git/config malicioso con una directiva sshCommand arbitraria.
  4. Cuando Gogs procesa el repositorio internamente y ejecuta operaciones git con SSH, el comando inyectado se ejecuta con los privilegios del proceso Gogs.

Primero registro un usuario en Gogs (los registros están abiertos) y creo un repositorio llamado asd. Luego, en el host, preparo el repositorio local y subo el symlink:

ln -s .git/config link
git add link
git commit -m 'add' && git push

Counting objects: 100% (3/3), done.

Total 3 (delta 0), reused 0 (delta 0), pack-reused 0
To http://localhost:3001/asd/asd.git

Exploitation Summary

The machine exposes a Flowise service on the subdomain staging.silentium.htb. The installed version (3.0.5) is vulnerable to several chainable CVEs. The entry point begins with user enumeration through the /api/v1/account/forgot-password endpoint, which responds differently depending on whether the email exists, allowing discovery of user ben@silentium.htb.

With the user identified, CVE-2025-58434 is abused: that same endpoint returns a valid tempToken in the response body that can be used directly against /api/v1/account/reset-password to reset the password without any further verification — a full Account Takeover.

Once authenticated, CVE-2025-59528 is exploited — an authenticated RCE on the /api/v1/node-load-method/customMCP endpoint that allows injecting arbitrary JavaScript via an unsanitized configuration field. This grants access to a Docker container where environment variables leak the SMTP password (SMTP_PASSWORD=r04D!!_R4ge), which also serves as the SSH password for user ben on the host.

On the host, a Gogs service is discovered listening on local port 3001. Version 0.13.3 is vulnerable to CVE-2025-64111, an RCE via a symlink attack that allows overwriting a repository's .git/config with attacker-controlled content, injecting an arbitrary sshCommand directive executed as root. This is leveraged to set the SUID bit on /bin/bash and escalate privileges.

CVE-2025-58434 affects Flowise's password recovery flow. The /api/v1/account/forgot-password endpoint not only accepts the email address — it returns the generated tempToken directly in the API response, rather than sending it only via email. This allows anyone who knows a valid email to take over the account without mailbox access.

Gogs RCE — CVE-2025-64111

The vulnerability abuses a symlink attack combined with the Gogs contents API. The flow is:

  1. Create a repository on Gogs and locally.
  2. Create a symlink pointing to .git/config and push it to the repository.
  3. Use the Gogs API to update the symlinked file's content, overwriting .git/config with attacker-controlled content containing an arbitrary sshCommand directive.
  4. When Gogs internally processes the repository and performs git operations over SSH, the injected command executes with Gogs process privileges.

I register a new user on Gogs (open registration is enabled) and create a repository named asd. Then on the host I prepare the local repo and push the symlink:
